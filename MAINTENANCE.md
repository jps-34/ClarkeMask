# Maintenance: development, release and signing

Notes for the author. Nothing here is needed to use the script. Same organisation as CommonCrop
and Badassium238.

## 1. Repositories

* **Development**: the private forge repository. Work happens on `dev/<topic>` branches, merged
  into `main` through pull requests reviewed by the author.
* **Publication**: only a final, validated version goes to the public GitHub repository
  `jps-34/ClarkeMask`, whose GitHub Pages site serves the PixInsight update repository from
  `docs/`: `https://jps-34.github.io/ClarkeMask/`.

### First publication on GitHub (not done yet)

1. The forge history starts with a commit created by the forge, which carries a personal e-mail
   address. Publish a fresh history instead: from a clean checkout of `main`, create a new
   repository with a single commit (or rewrite the author of the first commit), and check
   `git log --format='%an <%ae>'` before pushing: only the public identity and the GitHub
   no-reply address may appear.
2. Create the `ClarkeMask` repository on GitHub (public), push `main` and the version tags.
3. On GitHub: *Settings > Pages > Build and deployment > Deploy from a branch*, branch `main`,
   folder `/docs`.
4. Test: in PixInsight, *Resources > Updates > Manage Repositories*, add the URL above, then
   *Check for Updates*. Until it is signed, the *Allow unsigned update repositories* security
   option is required.

### Signing (not done yet)

Reference: *The PixInsight Code Signing System*, installed with PixInsight under
`doc/docs/CodeSigning/CodeSigning.html` (the former online address no longer works).

Signatures are recognised by every PixInsight user only for a **Certified PixInsight Developer**
(CPD). Steps, once:

1. Create a signing keys file (`.xssk`, password-protected) with the **SigningKeys** script.
2. Send the identity and the public key to Pleiades with the **SubmitCPD** script; the identity
   is added to the certified developers database of a later PixInsight release.

Then, for each version: sign the four scripts with the **CodeSign** script (one `.xsgn` file next
to each), run `tools/build_repo.py` (it packs the `.xsgn` files), and sign `docs/updates.xri`
last (the signature is embedded in it). The `.xssk` file stays out of Git (`.gitignore`). Until
then the repository is unsigned and users need the *Allow unsigned update repositories* option,
as the READMEs say.

## 2. Layout

* `scripts/`: the only sources to edit (V8, PixInsight 1.9.4 and later). `ClarkeMask.js` (dialog,
  menu entry), `ClarkeMask-WBPP.js` (WBPP event script), `ClarkeMaskEngine.js` (PixInsight layer),
  `ClarkeMaskCore.js` (numeric core, also run under node). The core namespace is built by
  `ClarkeMaskCoreFactory()`, which must stay self-contained: the engine sends its source code to
  the detection threads, with the engine helpers listed in `threadSource()` (keep that list in step
  with what `frameDetection()` calls).
* `tools/build_repo.py`: builds the update repository in `docs/` (archive with every script of
  `scripts/` and the license, SHA-1, `updates.xri`).
* `docs/`: generated by `tools/build_repo.py`, except `docs/index.html` (landing page of the
  repository URL), edited by hand.
* `DESIGN.md`: design notes and open questions.
* `DETECTOR.md`: every heuristic and parameter of the detector. **Any change to the detector
  (`ClarkeMaskCore.js`, detection part of `ClarkeMaskEngine.js`) updates this file in the same
  commit.**

## 3. Testing a development version

Numeric core, outside PixInsight (node and Python with numpy and astropy):

```bash
python3 -I tests/export_fits.py <frame.fits> <outside_the_repo>/frame1
node tests/run_core.js <outside_the_repo>/frame1
```

Parallel detection against serial, on the same frames (preview mode, frames untouched):

```bash
PixInsight.sh -n --automation-mode --no-startup-scripts \
  -r="<clone>/tests/run_group_pi.js,<run_1>,1,<frame1>,<frame2>,..." --force-exit
PixInsight.sh -n --automation-mode --no-startup-scripts \
  -r="<clone>/tests/run_group_pi.js,<run_auto>,0,<frame1>,<frame2>,..." --force-exit
python3 -I tests/compare_runs.py <run_1> <run_auto>
```

Scripts run with `-r` need `#engine v8` on their first line: without it, PixInsight 1.9 runs them on
the legacy SpiderMonkey engine (no `Array.from`, no `Thread`), where a relative `#include "../..."`
also fails without any message.

Dialog: *Script > Execute Script File*, pick `scripts/ClarkeMask.js` from a local clone (it
includes the core and the engine from its own folder; the installed version stays in place).
PixInsight 1.9 (V8): the PJSR classes (sizers, NumericControl, StdIcon, ...) are native; **do not
`#include <pjsr/Sizer.jsh>`**, it breaks the script before it starts (no error shown in automation
mode).

WBPP event script: in WBPP, *Pipeline > Event Script*, select `scripts/ClarkeMask-WBPP.js` from the
local clone (it loads the core and the engine from its own folder). The run log is written to
`<WBPP output>/ClarkeMask/ClarkeMask.log`. Registration must stay enabled in WBPP: the masking runs
at the end of that step.

End-to-end test without the GUI, in a separate automation instance (no settings saved; paths
without commas):

```bash
/opt/PixInsight/bin/PixInsight.sh -n --automation-mode --no-startup-scripts \
  -r="/opt/PixInsight/src/scripts/BatchPreprocessing/WBPP.js,automationMode=true,\
dir=<lights>,outputDirectory=<output>,usePipelineScript=true,\
pipelineScriptFile=<clone>/scripts/ClarkeMask-WBPP.js,localNormalization=true,\
integrate=true,generateRejectionMaps=true" --force-exit
```

Run it once without `usePipelineScript` into another output folder to compare the masters.

Never commit test images (FITS, XISF, drizzle or normalization files): their headers carry
location data. `.gitignore` excludes them.

## 4. Release of a version

1. On a `dev/<topic>` branch: set `var VERSION` in `scripts/ClarkeMask.js` (read by
   `tools/build_repo.py`) and `VERSION` in `scripts/ClarkeMaskCore.js` (written in the HISTORY
   keyword of masked frames), add the version line in the header of `ClarkeMask.js`, move the
   CHANGELOG section from *Unreleased* to the version.
2. Build the update repository:

   ```bash
   python3 tools/build_repo.py --user jps-34
   ```

   With signing, order matters: sign the scripts with **CodeSign**, run `tools/build_repo.py`,
   sign `docs/updates.xri` last, then commit.
3. Pull request on the forge; after the merge into `main`, tag the merge commit:

   ```bash
   git tag -a vX.Y.Z -m "ClarkeMask X.Y.Z"
   git push origin vX.Y.Z
   ```

4. Once published: push `main` and the tag to GitHub; in PixInsight, *Check for Updates*.

Getting a file from an older version: `git show v0.1.0:scripts/ClarkeMask.js > ClarkeMask-0.1.0.js`.

## 5. Versions

`MAJOR.MINOR.PATCH`: patch = bug fixed with no intended change in results, minor = new feature,
major = incompatible settings or results. Each version has its `vX.Y.Z` tag. The PixInsight
repository (`docs/`) only serves the latest one; older versions stay available through git.
